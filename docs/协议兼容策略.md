# 协议兼容策略

唯一参考实现：`reference/legacy/electron/vault-core.cjs`。快照哈希见 `reference/manifest.json`。不更换 LVCF 3，不降低 scrypt 参数。

## 已采用规则

- 固定 scrypt N=32768、r=8、p=1、32 字节输出；文件不能指定工作参数。该内核调用的内存工作量约 32 MiB，桌面宿主限制同一时刻一个阻塞业务操作，忙时返回 TRY_LATER，不排入无界 KDF 队列。
- AES-256-GCM 的 12 字节 IV、16 字节 tag、独立 base64 data 与旧版一致；AAD 使用规范 JSON 数组。
- Ed25519 公钥 SPKI、私钥 PKCS8 DER。解锁后校验公私钥身份。签名覆盖去掉 signature 的规范信封。
- canonical_js 使用 UTF-16 键排序和 ryu-js 数字序列化。serde_json 启用 float_roundtrip：默认浮点解析曾在专项对照中出现尾数差异，已修复并加入约 10,000 个确定性 IEEE-754 样本回归。
- 所有字符串长度按 UTF-16 计数；标题 trim 使用 JS 空白集合；可选字段缺失与 null 区分。扩展字段和附件对象保留旧版允许的额外字段。
- 24 分类、资产/附件/扩展字段数量、尺寸、时间与修订号安全整数上限逐项验证。修订号、恢复代次溢出显式拒绝。
- Owner 会话独有私有签名能力，Heir 不含私钥，无法调用修改、重包或配置。Session 不提供反序列化和 Debug。
- 密钥、派生材料、DER 临时缓冲区采用 zeroize；会话 Drop 擦除数据字符串。不能保证所有 JSON 临时分配、密码库内部工作区、系统缓存和 WebView 字符串消失；这不构成绝对内存擦除承诺。
- 重新包装 owner 保留 VMK 与恢复槽；显式 rotate_recovery 验证双凭据、生成新 VMK 和代次。旧份额仍能读对应旧备份，不做追溯撤销承诺。

## 明确的解析边界

- 最大输入 32 MiB；serde 默认递归深度限制保留（约 128 层）。超深输入拒绝为 `INVALID_FORMAT`，不重写源文件。
- 孤立 UTF-16 surrogate、非法 UTF-8、非有限/溢出的 JSON 数字拒绝为 `INVALID_FORMAT`。正常 emoji 和成对 surrogate 支持；禁止静默替换孤立 surrogate。
- 重复 JSON 键采用最后值，与 JSON.parse 相同。签名验证使用解析后的规范对象。
- Rust Value 不包含 undefined；不存在字段保持不存在，不生成 null 填充。显式 null 按旧模型规则验证。
- 本库是协议层；文件身份、本机版本/回滚策略、提交事务和会话 epoch 已由 vault-service 实现并有独立服务测试，不能把协议解密成功当作允许覆盖本机。

## 依赖选择

依赖精确版本与完整传递锁定见 Cargo.toml/Cargo.lock。采用 AES-GCM 0.10.3、scrypt 0.11.0、HKDF 0.12.4、SHA2 0.10.9、ed25519-dalek 2.2.0、zeroize 1.8.2。它们提供标准原语，本项目仅移植容器协议；尚未完成独立安全审计和发布级许可证/SBOM 审查。

API 核对依据：[Ed25519 DER 接口](https://docs.rs/ed25519-dalek/2.2.0/ed25519_dalek/pkcs8/)、[scrypt 参数](https://docs.rs/scrypt/0.11.0/scrypt/struct.Params.html)。
