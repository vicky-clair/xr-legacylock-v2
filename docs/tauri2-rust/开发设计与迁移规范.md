# LegacyLock：Tauri 2 + Rust 开发设计与迁移规范

日期：2026-09-24。适用范围：新建独立桌面项目，迁移当前 LegacyLock 1.0.6 系列的实际功能。本文是开发规范与验收计划，不代表 Tauri 版本已经实现或通过测试。

## 1. 产品目标与不可改变的约定

推荐架构：**Tauri 2 桌面宿主 + Rust 安全核心 + 复用 React/TypeScript/CSS 界面**。Node.js 仅用于开发构建与旧实现对照测试，正式应用不携带 Electron、Node.js sidecar 或本地 HTTP 服务。

“双快”定义为启动快、日常交互快；“双稳定”定义为数据保存与恢复稳定、桌面运行与平台集成稳定。包体积、运行内存和首次安装依赖分别统计。所有性能数字先作为工程目标，不能宣传为已达到的结果。

优先级：数据兼容与完整性 > 权限正确 > 原有功能与界面 > 性能 > 包体积。不能通过减少密码派生强度、跳过验签/读回、移除功能或不计运行库体积来完成性能指标。

首版沿用 LVCF 3 文件协议，保留原有背景、三栏布局与所有有效功能。不要同时更换前端框架、改数据库、改加密算法、引入真实支付或重新设计 UI。Rust 并不自动修正错误的业务授权，Tauri 也不自动保证备份安全。

## 2. 迁移基线与资料准备

以冻结的源码快照为基线，不能只写“1.0.6”：同版本号下仍可能有未提交修改。保存快照日期、Git 提交（如有）、文件 SHA-256 清单、依赖锁文件、运行截图与合成测试样本。新项目使用独立应用标识和独立数据目录，迁移测试不得指向真实密库。

需要从旧项目复制到新项目 `reference/legacy/` 的参考资料：

| 双盘只读导入 | 选择备份并读取两份有效份额，内存打开，允许查看旧备份或另一密库，不覆盖本机 |

| 接管 | 继承只读会话需要手动输入该备份的密码与安全密钥；写本机前仍检查身份及版本，不使用本机记住的密钥代替 |

字段类型保留 `text/url/email/address/date/totp/password/phone/note`。`totp` 类型的存在不代表已经实现动态验证码；迁移时按原来的真实能力保留，不能凭类型名称擅自扩展产品承诺。

## 4. Tauri 2 与 Rust 特性采用策略

“多用新特性”应体现在减少权限面、阻塞和复制，不能变成无关插件堆积。

| 特性 | 采用方式 | 约束 |
|---|---|---|
| Tauri 2 capabilities / permissions / scopes | 将权限约束到主窗口和实际用到的命令；平台能力分别配置 | 业务角色仍由 Rust 验证，不能靠按钮 disabled 或 capability 动态切换代替 |
| 应用命令显式 ACL | 使用 `AppManifest::commands` 纳入应用命令清单，生成/定义并审查权限 | 默认注册的应用命令并非自动受你想象中的细粒度 ACL 保护 |
| typed commands + Serde DTO | 固定命令、明确参数与错误码；TS 绑定使用单一来源生成或一致性校验 | 禁止任意文件读写、执行命令、设置角色的通用接口 |
| `Channel<T>` | 导入、导出、扫描及备份进度按操作定向推送 | 进度不携带密钥、完整资产或文件正文；限频、可丢弃过期进度 |
| 异步 commands + 阻塞工作池 | 密码派生、签名、文件及设备操作离开 UI 线程 | KDF 限制并发，不能随意开启无限线程 |
| 原始字节 IPC | 后期针对确实需要传入 WebView 的附件预览评估，减少 base64 膨胀 | 文件落盘优先由 Rust 完成；不开放任意本地路径 |
| Tauri 2 原生托盘、菜单和窗口 API | Rust 管理关闭流程、托盘恢复及单实例窗口唤起 | 三平台单独测试；无托盘环境不隐藏唯一窗口 |
| 官方 single-instance 插件 | 尽早注册，辅助阻止重复桌面实例 | 另外使用密库文件锁；不同应用标识、旧版 Electron 不一定共享单实例锁 |
| `build.removeUnusedCommands` | 能力清单完整且静态后启用命令裁剪 | 官方列出最低组合：tauri 2.4、tauri-build 2.1、tauri-plugin 2.1、CLI 2.4；实际采用锁定的兼容稳定版本 |
| Rust 所有权、枚举、Result、RAII | `Locked/Owner/Heir` 明确状态；秘密生命周期显式管理 | `unsafe` 限于必要 OS FFI 模块，单独审查 |
| Rust stable、Edition 2024 | 在工具链与依赖兼容验证后作为新工程基线 | 固定工具链版本；不以 nightly 特性支撑正式版 |

能力规则与应用命令默认行为依据 [Tauri capabilities](https://v2.tauri.app/security/capabilities/)；命令/Channel 依据 [Calling Rust](https://v2.tauri.app/develop/calling-rust/)；命令裁剪依据 [App Size](https://v2.tauri.app/concept/size/)。这些机制是 Tauri 2 的可用工具，表中具体取舍是本项目设计。

首版不要默认安装 HTTP、Shell、SQL、远程更新、自动启动和文件系统前端插件。原生文件选择、剪贴板、窗口状态等按实际需要引入，尽可能由 Rust 包装。**Stronghold 是加密秘密存储方案，不自动等于 Windows DPAPI/macOS Keychain，也不会自动兼容 Electron safeStorage 文件。**本项目已有 LVCF 3，不为追新而更换文件格式；本机记住密钥优先使用 OS 适配层。[Stronghold 官方文档](https://v2.tauri.app/plugin/stronghold/)

复制原 `App.tsx`、`Sidebar`、`RightContentArea`、`ItemModal`、`CategoryPickerModal`、`BackupImport`、`SubscriptionModal`、主题、图标、字典和 CSS。第一阶段只替换 bridge；不要重新实现视觉组件。Electron preload/main 不能带进 WebView。已删除的旧弹窗与旧迁移路径不重新恢复。

定义内部 `DesktopBridge`，保留原 `call(method, ...args)` 和 `{ok,value}/{ok:false,error}` 语义。Tauri 异常在适配层统一转为原错误码；显式建立旧 camelCase 方法名与 Rust snake_case 命令名的对应关系。不要把原位置参数数组直接透传给 `invoke`，应转换成每条命令要求的具名参数对象。

旧 `window.vaultAPI` 的依赖逐步改为模块引用；不得通过全局对象注入“已解锁”角色。订阅、UI 与文件选择的取消仍返回 `canceled`，不得被成功提示覆盖。

视觉基线：Windows 1180×800、800×500，另验证高 DPI、85/100/115/125% 缩放、三种语言和五套背景。允许系统字体和窗口边框有平台差异，三栏结构、入口顺序、颜色、按钮对齐和用户操作路径不得任意改变。WebView2、WKWebView、WebKitGTK 的滚动条、`dialog`、焦点与下载行为分别测试，不能把 Chromium 截图通过当作三平台通过。

## 6. IPC 与权限契约

生产仅一个本地主 WebView。禁止远程页面获得 capability，禁止任意导航、新窗口及资产 HTML 执行。资产、备注与附件名称只作为文本显示，不使用 `dangerouslySetInnerHTML`。附件导出通过 Rust 原生保存对话框完成，不依赖不同 WebView 对 `<a download>` 的实现。

| 旧方法/事件 | Rust 服务责任与前置条件 |
|---|---|
| `status`、`preferences`、`localUnlockStatus` | 返回有限状态与非秘密偏好；不能返回密钥或解密后的 sidecar |
| `newSecret` | OS 安全随机生成 LL3；只在创建/更换流程显式返回，禁止日志记录 |
| `initialize` | 本机无密库；验证创建凭据及容量；写入后验证 |
| `unlock` | 手动双凭据；本机或当前继承备份接管；接管写入前执行身份/回滚检查 |
| `unlockLocal` | 只接受锁定的本机密库；系统密钥库可用、绑定匹配、密码正确；禁止继承会话使用 |
| `setRememberedSecret` | 启用需 Owner + 再次手动双凭据；取消需 Owner |
| `lock`、`activity`、`onLocked` | Rust 锁定为权威；activity 限频；onLocked 清理 UI 和旧请求结果 |
| `saveItem`、`deleteItem` | Owner、合法模型、演示未到期；串行提交；不得信任前端 revision |
| `settings`、`setPreferences` | Owner、白名单值；敏感设置进入密库，外观偏好单独保存 |
| `viewLanguage` | 临时语言可在锁定/继承状态使用，不持久化、不改变权限 |
| `scan` | OS USB 扫描，返回临时 token 和展示信息，不给前端任意路径能力 |
| `provision` | Owner + 新鲜双凭据 + 两块不同物理 USB；轮换与双盘提交协议 |
| `sync` | Owner + 主盘份额验证，保留副盘；成功返回已写入版本 |
| `recover` | 双份额验证、选择备份、只读内存会话，禁止覆盖本机 |
| `importOwner` | 源备份双凭据；首次/锁定导入遵守身份及版本规则 |
| `importData` | 已有 Owner；源文件双凭据；合并不替换本机身份、设置与份额 |
| `export` | Owner + 再次双凭据；导出信息容器，不导出本机记忆 |
| `credentials` | Owner + 旧双凭据；新凭据有效；只重包 owner 槽并使本机记忆失效 |
| `health` | 有会话；检查签名、格式和本机/当前读取源的一致性 |
| `prepareDestroy`、`destroy` | 双凭据生成有时效的单次令牌；第二次确认、绑定校验与限定目录清理 |
| `copy` | 已解锁；按原权限允许复制，定时/锁定时安全清理 |
| `windowControl` | 固定枚举 minimize/maximize/close/quit/tray，由 Rust 处理生命周期 |

初版可完整复现旧 DTO 以减少 UI 迁移风险。性能阶段再加入 `listItems/getItem/exportAttachment` 等分页/按需接口，旧 `view()` 不再把全部附件和秘密反复送到前端；由适配层和组件内部状态调整实现，外观不变。这个优化需要独立验收，不能一面承诺 IPC 只传摘要、一面仍传整库。

自定义命令清单必须在 `build.rs` 用 `AppManifest::commands` 显式注册到权限体系，并与 `generate_handler!`、capabilities 保持一致。只给 `main` 所需权限，避免 `windows:["*"]`、全盘 fs、shell、HTTP 等宽泛授权。若为插件私有 Rust 调用，不为方便额外开放其 JS 命令。

CSP 使用 Tauri 所选版本的本地协议/IPC要求，保留框架注入的必要机制；禁止远程脚本、远程字体、远程 API 和 `unsafe-eval`。旧界面大量内联 style，应优先保留外观并单独评估 style 约束，不能为兼容样式把脚本策略一起放开。静态 CSP 和外部导航拦截联合测试。[Tauri CSP](https://v2.tauri.app/security/csp/)

## 7. LVCF 3 兼容规范：先完成，再接入真实数据

下面是必须落实的协议摘要；精确验证规则以冻结的 `vault-core.cjs` 与测试向量为准，不以旧注释中的宣传措辞为准。

| 项目 | 要求 |
|---|---|
| 信封 | `magic=LEGACYLOCK`、`format=3`、id、revision、signingPublicKey、owner、recovery、payload、signature；严格字段集合 |
| AES | AES-256-GCM；随机 12 字节 IV、16 字节 tag；三个字段 iv/tag/data 使用规范 base64 |
| AAD | UTF-8 的规范 JSON 数组 `["LVCF3", id, signingPublicKey, kind]` |
| payload | VMK 加密 `{items,settings}`，kind=`payload` |
| Owner KDF | scrypt N=32768、r=8、p=1、输出 32 字节；实现资源预算对齐原 64 MiB maxmem 约束；不能让文件指定任意参数 |
| KDF 输入 | `[password, lowercaseSecretHex]` 的 JSON UTF-8，password 不 trim、不做 Unicode 规范化 |
| 安全密钥 | 原有 LL3 格式与解码容忍规则，随机 32 字节；不能截断、哈希用户输入来“兼容”错误密钥 |
| owner | 16 字节 salt；加密 `{vmk,signingPrivateKey}`；私钥 Ed25519 PKCS8 DER，公钥 SPKI DER，均规范 base64；kind=`owner` |
| 签名 | Ed25519，对去除 signature 字段后的完整规范信封签名；解包私钥后核对公钥身份 |
| 双盘 | 独立随机 32 字节 A/B，HKDF-SHA256 输入 A||B、salt=UTF-8 id、info=`LVCF3 recovery <generation>`；输出 32 字节 |
| recovery | 仅包 VMK，不含签名私钥；kind=`recovery:<generation>`；份额身份、角色、代次与签名均验证 |
| 限额 | 容器 32 MiB、资产 JSON 20 MiB、10,000 项、单附件 2 MiB；扩展字段/附件数量及字符串上限逐项移植 |

跨语言陷阱必须有专项测试：

1. 旧对象键按 JavaScript UTF-16 code unit 排序；Rust 默认字符串排序不是同一个规则。实现 `canonical_js`，不要直接使用 `serde_json::to_string` 或任意“canonical JSON”库替代。
2. 字符长度按旧 JS UTF-16 语义计算，密码 12～1024、时间/修订号限制为 JS 安全整数。不能直接用 UTF-8 字节数代替字符数；安全整数最大值为 2^53−1。
3. JSON 字符串转义、控制字符、非 BMP 字符、负零、数字序列化、缺失字段与 null 分别测试。孤立 surrogate 在 Rust String 中无法直接表示：兼容读取策略必须显式设计，遇到不支持输入保留原文件并报可识别错误，禁止静默替换字符。
4. `undefined` 不是 JSON 值，旧对象序列化省略相关字段；Rust `Option` 的省略策略必须匹配，不能统一写成 null。
5. Ed25519 不能把 DER 与 raw key 字节混用；GCM crate 可能把 tag 拼在尾部，必须转换到原三个字段结构。
6. 区分原实现严格拒绝的顶层未知字段与扩展对象中的旧版允许内容；不要用统一的 Serde `deny_unknown_fields` 静默改变所有层级的兼容性。新增解析深度、重复键和资源上限要记录明确策略，并用历史合成样本验证。
7. 不期待随机加密产生相同文件字节。生产双向测试验证可解密、签名正确及内容相同；固定随机数只用于测试向量，禁止进入生产构建。

推荐依赖方向为 RustCrypto 的 AES-GCM、scrypt、HKDF/SHA-256，以及成熟 Ed25519 实现；具体 crate、版本、特性和许可证在 P1 做依赖审查后锁定。禁止自制密码算法。整个 `vault-core` 不依赖 Tauri、数据库和平台密钥库，便于独立测试和离线阅读器复用。

### 双向互操作发布门槛

- Node 写 → Rust 验签、密码+密钥解锁、双盘解锁。
- Rust 写 → Node 验签、密码+密钥解锁、双盘解锁。
- Node 写 → Rust 修改 → Node 读取；Rust 写 → Node 修改 → Rust 读取。
- 附件字节与 SHA-256、Unicode 备注、空字段、分类和时间完全保留。
- Node 配置的旧副盘在 Rust 日常主盘更新后仍能读取；更新前后副盘文件哈希相同。
- Rust 更换所有者凭据后，旧凭据失败，原双盘继续成功。
- 显式重配后旧份额不能读新代次，旧备份仍按旧凭据可读，不宣传追溯撤销。
- 当前 fixtures 只是起点，不是完整认证；补充边界、损坏与跨平台样本。

## 8. Rust 会话、并发与锁定设计

建议用服务 actor/串行写入队列组织数据修改，用独立的原子 epoch 作为失效代次。内部类型为 `Session::Locked / Owner(OwnerSession) / Heir(HeirSession)`，Owner 才包含签名能力。此类型不得由 IPC 反序列化输入决定。

执行耗时工作前取 epoch；密码派生或文件读取结束、授予会话前、写入提交前以及回复 UI 前都重新检查。锁定请求不排在漫长 KDF 或 USB 写入队列尾部：先增加 epoch、拒绝新操作、移除当前会话并通知 UI，再让已开始工作自行结束并丢弃失效结果。UI 同样忽略过期请求，防止锁屏后慢请求重新显示资产。

`spawn_blocking` 用于有限的 CPU/阻塞 I/O 工作，KDF 初期最多 1 个并发任务，结合有界队列/信号量和重试节流。不能持有全局 Mutex 跨整个 `.await`。已开始的阻塞任务无法靠 `abort` 强行终止，必须使用 epoch 与阶段检查保证不会重新授权。[Tokio spawn_blocking](https://docs.rs/tokio/latest/tokio/task/fn.spawn_blocking.html)

锁定时销毁 Rust 会话秘密，清理前端详情、编辑器、密码输入、附件预览及 clipboard；阻塞工作中的临时副本完成后也销毁。使用 `zeroize`/秘密封装降低残留风险，不给秘密类型派生 Debug，不克隆整份会话。它不能保证 WebView/JS 字符串、OS 缓存、swap、崩溃转储或硬件寄存器全部消失。[zeroize 文档](https://docs.rs/zeroize/latest/zeroize/)

对非预期 panic：错误边界使服务进入锁定/不可继续写状态，禁止吞掉 panic 后继续提交。默认保留 unwind 以利诊断，是否使用 abort 是后期体积实验，不能假设 abort 会运行 Drop 清零或保存数据。

## 9. 磁盘事务、双盘与跨平台适配

### 9.1 单文件提交

保留串行写、同目录临时文件、文件 sync、结构与签名读回、`.previous`、平台原子替换和替换后验证。临时文件使用不可预测名称、独占创建和最小权限。不要用“删除目标 → 重命名”伪造原子替换。

Windows 需验证目标存在时的 ReplaceFile/替换语义及文件占用行为；Unix 验证 rename 与父目录同步。保存前比较本机身份及修订号，应用/文件锁防止并发写。不可确定是否已替换成功时强制锁定并重新读取，不返回虚假的“保存失败但仍可继续编辑”。具体 OS 调用封装成可注入的 `AtomicVaultWriter`。

“fsync 成功”不等于对所有 USB 控制器、文件系统和断电场景提供绝对保证。FAT32、exFAT、NTFS、APFS、ext4 分别做适用平台测试，写保护、空间不足、权限错误、文件占用、拔盘、系统关机均需有明确恢复路径。

### 9.2 USB 配置与更新

`MediaProvider` 返回卷展示信息与短期 token，在 Rust 内部解析真实路径及物理设备身份。token 每次扫描刷新；选择后和写入前再次确认设备未变化，拒绝系统盘及同物理盘分区。盘符和标签不构成物理身份。序列号可能缺失或重复，不把它宣传为防克隆硬件认证。

Windows 优先评估原生设备/卷 API，macOS 评估 Disk Arbitration/IOKit，Linux 评估 udev/sysfs 与挂载信息。初版允许保留旧实现的绝对路径系统工具调用作为过渡，但使用固定参数、隐藏窗口、超时、输出限额，绝不将用户输入拼入 shell。

配置目录沿用 `LegacyLock/<id>/<generation>/`。两盘文件全部写入、同步、读回验证后再提交本机配置。跨盘没有统一原子事务，采用新代次目录与失败保全策略，不覆盖工作中的旧代次。日常主盘同步仅写 `vault.llvault`，不得强制请求副盘。

插拔事件优先用于快速检测，并用低频复核弥补平台事件遗漏；检测到继承会话任一所选盘消失即锁定。扫描超时不能冻结 UI。缓存扫描结果用于展示，不能缓存为永久授权。

## 10. 本机记住安全密钥

定义 `LocalSecretStore` trait：`availability / seal / unseal / delete`，OS 后端只在 Rust 可访问。Windows 使用用户范围 DPAPI 或经审查的等效系统凭据方案，macOS Keychain，Linux Secret Service/KWallet 适配；没有可靠存储时功能不可启用，不使用硬编码密码或明文降级。

新记录使用独立格式版本、密库 id/根公钥/owner 槽 SHA-256 绑定；保存加密密文或凭据引用，不进入信息导出、USB、普通偏好或日志。启用需 Owner + 新鲜手动双凭据，取消需 Owner；即使系统密钥库暂不可用，也应能取消本机记忆。解密后的秘密只用于本机锁定状态的 owner 解锁，不回传 UI，不代填导出/删除/接管/重配的双凭据校验。

旧 Electron `local-key-v1.json` **默认不自动迁移**。新应用首次要求手动密码+安全密钥，再由用户主动重新启用。不能假定 Electron 的密文包装和各平台 Rust 凭据 API 一致。保留旧文件原件，迁移不能让原应用丢失其独立数据。

普通资产保存和主盘更新保留记忆；owner 槽变化、显式双盘重配、删除本机密库应使记忆失效或删除。安全失败时退回手动双凭据，明确提示，不创建空密库。Windows 同一账户中的恶意程序仍可能读取系统保护的数据；Rust 不改变这个 OS 威胁边界。[Electron safeStorage 平台语义](https://www.electronjs.org/docs/latest/api/safe-storage)

## 11. 原生桌面生命周期

托盘、主窗口与密库会话分别建模。关闭确认使用 Rust 原生对话框和重入保护；用户选择托盘时先验证托盘图标/菜单创建成功，再锁定和隐藏。退出先撤销会话权限，等待已接受提交到达明确结果后结束；不强行中断正在替换的文件。崩溃后重启只显示锁定或损坏状态。

single-instance 插件按官方初始化顺序接入，第二实例仅唤起旧窗口，不接受命令行携带密码和密钥。另加文件级互斥锁避免独立便携目录、不同应用 ID 与旧版同时写同一文件。[Single Instance](https://v2.tauri.app/plugin/single-instance/)

托盘在平台间行为不完全相同，Linux 桌面可能缺少托盘支持；分别实现可用性探测与保留窗口回退。睡眠/系统锁屏应通过平台事件适配，不假设一个窗口失焦事件就等同系统锁屏。[System Tray](https://v2.tauri.app/learn/system-tray/)

不默认加开机启动、全局热键、后台自动扫描全盘或外链打开。若需要打开资产 URL，后续另行设计用户明确点击、允许 scheme 和 opener 权限，首版保持原有功能。

## 12. 性能与体积工程

### 12.1 实施顺序

1. 首屏先显示锁定界面，不等待 USB 扫描、密钥库解锁或导入文件解析。状态检查不等于解密整库。
2. 保留现有组件懒加载；本地打包字体/图标/背景，不添加 CDN、图标大全、Node sidecar 或无关 UI 库。
3. 主列表超过阈值采用虚拟列表，保留键盘、选中项和辅助技术语义。搜索做短去抖、取消旧请求，旧结果不能覆盖新结果。
4. 详情与附件按需读取；附件在 Rust 原生导入/导出，旧 `.llvault` 内仍用兼容表示。内部用字节结构避免多份 base64，落盘时按原协议编码。
5. 保持完整提交的可靠性。保存耗时先测序列化、加密、同步、验签各段；不能直接去掉 fsync 或读回。
6. 每次可观察到的保存成功对应一个确认提交。若未来合并连续写请求，必须设计每个调用的完成语义和异常恢复，首版不偷偷使用“内存保存成功”。

### 12.2 测量与目标

固定测试机、系统版本、WebView 版本、磁盘、杀毒设置和电源模式；分别测试安装版、便携版，20 次冷启动及 20 次热启动。记录 p50/p95，不混合首次 WebView 初始化、运行库安装和普通启动。数据集含 100/1,000/10,000 项，容量不得超过兼容上限；大附件集另测。

| 指标 | 初始工程目标（须实测后确认） |
|---|---|
| 锁定界面可输入 | 指定 SSD 参考机热启动 p50 ≤ 700ms、p95 ≤ 1.5s，并与相同条件的 Electron 基线比较 |
| 切换条目 | 1,000 项 p95 ≤ 100ms；10,000 项 p95 ≤ 150ms，附件下载不混入该指标 |
| 搜索结果可见 | 10,000 项含去抖 p95 ≤ 250ms，输入不明显阻塞 |
| 锁定响应 | UI 和授权撤销目标 ≤ 100ms；异步任务用 epoch 丢弃，不声称内核 I/O 同时终止 |
| 运行内存 | 主进程 + WebView 所有相关进程合计，同条件争取比基线降低 30%；未实测不作为宣传数字 |
| Windows 精简安装包 | 不含 WebView2 的包目标 ≤ 20 MiB，目标未达时输出依赖体积分析；完整离线包单独统计 |
| 保存可靠性 | 所有故障注入场景不得报告未确认的成功，不得自动清空，不以耗时目标否决必要验证 |
| 解锁耗时 | 报告 KDF 与其他步骤的独立 p50/p95，保持原参数，不承诺通过换语言消除故意的派生成本 |

旧项目记录过约 546ms 的隔离环境锁屏启动中位数，但样本仅 3 次，不含真实便携解压和大数据，不应作为新项目达标证明。重新测完整基线，若当前版本更快，以相同条件新测结果为准。

### 12.3 Cargo 配置候选

以下是性能优先的发布起点，放在 workspace 根 `Cargo.toml`，不是已经验证的最优配置：

```toml
[profile.release]
opt-level = 3
lto = "thin"
codegen-units = 1
strip = "debuginfo"
panic = "unwind"
```

另测 `opt-level="s"`、`lto=true` 的体积优先配置，记录包体积、KDF、解析、搜索和构建时间后选择。不要先全局 `opt-level="z"` 再承诺所有计算更快；不要设置 `target-cpu=native` 制作通用发布包。调试符号可另存发布归档，不放进用户安装包。增量开发采用默认开发 profile，依赖优化按瓶颈实测选择。[Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html)

裁剪未使用依赖和 crate features；Tauri 命令裁剪只在完整静态权限审查后启用。正式构建禁止把 reference、测试图片、开发缓存、node_modules、源映射和密钥样本带入包。锁定依赖、构建缓存、按平台 CI 提高构建效率，不能保证 Rust 的全量编译比 TS 快。

不把 UPX/商业加壳作为默认优化：可能影响杀毒、签名、启动和崩溃诊断；源代码混淆也不替代数据加密。需要时作为独立实验，不阻碍数据恢复、更新签名及托盘兼容。

## 15. 数据迁移、测试与发布门槛

默认迁移方式：旧版导出 `.llvault` → 新版在独立目录验证并导入，旧文件不动；现有两份 USB 份额继续作为兼容对象使用，不要求重配。提供显式“迁移旧版密库”流程时，先只读发现、展示路径和版本、要求用户选择，再复制到新目录验证；禁止扫到文件就自动解锁或原地转换。新项目不自动读取或迁移旧本机记住密钥文件。

导入测试不能把“拒绝旧备份覆盖本机”和“允许继承人查看旧备份”混为同一规则；这是两个不同流程。相同记录跳过、冲突记录生成新副本的合并逻辑要保持，不使用整库覆盖来简化实现。

### 测试分层

| 层级 | 必须覆盖 |
|---|---|
| Rust unit/property | canonical_js、模型边界、KDF、AEAD、签名、角色状态、秘密生命周期、错误码 |
| Node↔Rust 对照 | 第 7 节全部双向操作；旧 fixtures、Unicode、附件、凭据轮换和副盘不变 |
| 故障注入 | 每一写入阶段的断开、占用、无空间、短读、读回失败、rename 后未知结果、锁定并发 |
| 权限负面测试 | 锁定/继承人直接 invoke 写操作失败；伪造 role/路径/token/权限失败；删除令牌重放失败 |
| UI 回归 | 三栏点击、密码重新隐藏、搜索空结果、编辑失败不丢内容、附件入口、三语言、五主题、缩放、订阅演示 |
| 桌面集成 | 原生托盘图像真实解码与创建、关闭三分支、系统锁屏、休眠、单实例、剪贴板异常 |
| 系统密钥库 | 首次启用、重启解锁、取消、后台不可用、损坏、凭据变化、继承人越权、删除清理 |
| 真实硬件 | 两个分区拒绝、盘符变化、拔盘/重插、设备标识变化、主盘单独更新、写保护及断电 |
| 发布物 | 安装/卸载/升级不删密库；签名、哈希、资源、语言、图标、离线依赖与恢复阅读器 |

现有 36 项 Node 测试是迁移需求，不是 Rust 通过证明。Node 参考实现留在 CI 对照区，不能作为正式运行时后门。模糊测试仅使用隔离目录与合成文件，不运行真实删除和用户盘写入。

Tauri WebDriver 可用于 Windows/Linux 自动化；macOS 官方没有对应的 WKWebView WebDriver 桌面驱动支持，不能写成三平台同一套 tauri-driver 已覆盖。macOS 用 Rust 单元/协议测试、前端组件测试、平台集成和实际人工 UI 检查补齐。[WebDriver 官方说明](https://v2.tauri.app/develop/tests/webdriver/)

退出测试必须确认队列终态；崩溃恢复后应出现完整旧版或完整新版，不能出现可继续写的半提交状态。每个发布候选都在断网环境验证创建、解锁、导入导出、双盘及阅读器。

建议 CI：`npm ci` → 前端类型/构建 → `cargo fmt --check` → `cargo clippy --workspace --all-targets --locked -- -D warnings` → `cargo test --workspace --locked` → 互操作 → 平台 UI/集成 → release 构建 → 安装包检查。`--offline` 只用于已准备完整依赖缓存的可复现离线流水线，不能假设新电脑首次构建无需下载依赖。

## 16. 分阶段交付与停止条件

| 阶段 | 交付物 | 放行条件 |
|---|---|---|
| P0 基线 | 源码快照、功能矩阵、UI 截图、性能基线、黄金样本 | 用户现有功能全部可追溯，未接触真实数据 |
| P1 协议与阅读器 | Rust vault-core、canonical_js、离线 reader | 双向互操作全通过；否则停止 UI 功能迁移，不换格式绕过 |
| P2 宿主与旧 UI | Tauri 窗口、bridge、同外观界面、应用命令 ACL | 入口不丢失、无宽泛权限；占位后端明确标注且不得对真实数据报告成功 |
| P3 所有者流程 | 创建、解锁、CRUD、文件事务、导入导出、记住密钥 | 故障注入、锁定竞态、旧备份互操作通过 |
| P4 继承与桌面 | USB、继承只读、托盘、系统锁屏、单实例、设置 | 三平台关键行为及真实双盘验证通过 |
| P5 性能与包体积 | 按需 IPC、虚拟列表、依赖裁剪、两种 Windows 分发 | 提供测量原始数据与依赖完整清单；不牺牲安全/界面达标 |
| P6 发布候选 | 签名包、哈希、迁移/恢复手册、版本说明 | 原功能矩阵全通过，旧密库无需重配双盘，可回退使用原数据副本 |

发现协议不兼容、静默丢字段、继承人可写、损坏文件被重置、旧副盘失效、锁屏后重新显示秘密等任一情况，停止发布；保存证据并修正，不用提示文案掩盖行为问题。不同平台未验证则只发布已经通过验证的平台，不声称“三平台已认证”。

## 17. 给新项目开发者的启动指令

可将下面这段连同本文件及冻结的旧源码交给新项目开发者：

> 基于此规范建立独立的 Tauri 2 + Rust 工程。保留旧 React/TypeScript/CSS 界面、全部有效功能及 LVCF 3 兼容。先输出 P0 基线清单，然后实现 P1 Rust 协议库与独立阅读器，使用旧 Node 实现做双向互操作。P1 未通过，不接入真实密库、不自行换算法或格式。之后按 P2～P6 逐步替换宿主、会话、USB、系统密钥库和托盘。所有文件访问与授权在 Rust；前端不能设置角色、访问任意文件或拿到记住的安全密钥。性能和体积必须附同条件实测，不能以降低 KDF、跳过读回或移除功能换取数字。每阶段列出已完成项、测试证据、未验证平台和兼容问题。

附属执行清单见 [分阶段验收清单](分阶段验收清单.md)。
